# Задачи

Порядок важен: сначала то, что нужно на ближайшей партии.

## 1. Расширение Owlbear Rodeo: бросатель кубов V20

**Зачем.** В Owlbear нет удобных кубов для V20: пул d10 со сложностью, отмена успехов единицами, ботчи, специализации. Готовые расширения (dddice, Chronicle!, Dashboard Maker) этого не умеют.

**Как устроены расширения Owlbear.** Расширение — это обычный веб-сайт, который Owlbear открывает во встроенном окне внутри комнаты. Описывается файлом `manifest.json` (название, иконка, URL страницы, action-кнопка в левом верхнем углу). Подключается так: профиль Owlbear → Add Extension → ссылка на `manifest.json`, потом расширение включается в настройках комнаты. Общение с Owlbear идёт через SDK `@owlbear-rodeo/sdk` (TypeScript).

Документация:
- https://docs.owlbear.rodeo/extensions/getting-started/
- https://docs.owlbear.rodeo/extensions/apis/
- пример: https://github.com/owlbear-rodeo/sdk-tutorials/tree/main/hello-world

**Ограничения, которые надо учесть.**
- `OBR.room` metadata: всего не больше 16 КБ на комнату, на все расширения вместе.
- `OBR.broadcast`: сообщение не больше 16 КБ. Сообщения эфемерные, не сохраняются.
- Лимиты для `OBR.player`, `OBR.scene` и метаданных предметов в документации не указаны. Проверить на практике, прежде чем на них полагаться.
- Ключи метаданных по соглашению Owlbear должны иметь префикс в стиле обратного домена, например `io.github.greenradiation.vtm/rolls`.

**Где лежит.** В этом же репозитории, например исходники в `owlbear/` (Vite + TypeScript), а собранное расширение раздаётся GitHub Pages по адресу вида `https://greenradiation.github.io/vtm-game-map-data-ru-dallas-2005/owlbear/manifest.json`. Сборку удобнее всего делать GitHub Actions, которые собирают расширение и публикуют весь сайт (карту плюс расширение) в Pages. Если перейдёшь на Actions, переключи источник Pages на «GitHub Actions» в настройках репозитория и проверь, что карта по-прежнему открывается.

**Правила броска V20 (уточнить у мастера, что из этого используется).**
- Бросается пул d10. Пул = атрибут + способность (или что скажет мастер), плюс и минус модификаторы.
- Сложность от 2 до 10, по умолчанию 6. Каждый куб со значением не ниже сложности даёт успех.
- Каждая выпавшая единица отменяет один успех.
- Если успехов не выпало вовсе и есть хотя бы одна единица, это ботч (провал с катастрофой). Если успехи были, но единицы их все отменили, это обычный провал, не ботч.
- Специализация: при броске со специализацией каждая десятка даёт два успеха.
- Сила воли: трата 1 пункта даёт 1 автоматический успех. Уточнить у мастера, могут ли единицы его отменять.
- Пул 0 и меньше: бросок невозможен, если мастер не скажет иначе.
- Отдельно пригодятся: инициатива (1d10 + Ловкость + Смекалка, без сложности), простой бросок «чистых» d10 без подсчёта успехов, урон и поглощение (обычный бросок по сложности 6).

Логику подсчёта вынести в отдельный чистый модуль и покрыть тестами: обычный успех, отмена единицами, ботч, провал без ботча, специализация, Сила воли, граничные сложности 2 и 10.

**Интерфейс.**
- Action-кнопка открывает попап: поле пула (или кнопки ±), сложность, галочки «специализация» и «Сила воли», необязательная подпись броска («Ловкость + Атлетика»), кнопка «Бросить».
- Результат показывает все кубы, подсвечивает успехи, десятки и единицы, итог словами: «3 успеха», «провал», «ботч».
- Бросок видят все в комнате: рассылка через `OBR.broadcast` и короткое уведомление через `OBR.notification`. В попапе есть лента последних бросков (20–30 штук) с именем игрока и временем. Ленту хранить в метаданных комнаты компактно, обрезая старые записи, чтобы не выйти за 16 КБ.
- Опция «скрытый бросок мастера»: результат видит только GM (проверка роли через `OBR.player.getRole()`).
- Русский интерфейс. Тёмная и светлая тема по `OBR.theme`.

**Готово, когда:** расширение подключается по ссылке на manifest, два человека в одной комнате видят броски друг друга, тесты логики проходят, лента переживает перезагрузку страницы.

## 2. Расширение Owlbear Rodeo: лист персонажа V20

**Содержимое листа V20.**
- Шапка: имя, игрок, хроника, натура, маска, концепция, клан, поколение, сир.
- Атрибуты (1–5): Физические — Сила, Ловкость, Выносливость; Социальные — Обаяние, Манипулирование, Привлекательность; Ментальные — Восприятие, Интеллект, Смекалка.
- Способности (0–5): Таланты, Навыки, Познания по 10 штук в каждой группе по V20 (например, Бдительность, Атлетика, Осведомлённость, Драка, Эмпатия, Экспрессия, Запугивание, Лидерство, Знание улиц, Хитрость; Обращение с животными, Ремесло, Вождение, Этикет, Стрельба, Воровство, Фехтование, Исполнение, Скрытность, Выживание; Гуманитарные науки, Компьютер, Финансы, Расследование, Право, Медицина, Оккультизм, Политика, Естественные науки, Технологии). Специализации к атрибутам и способностям.
- **Русские названия нужно взять из русского издания, по которому играет группа.** Перед реализацией попроси автора прислать список или скриншоты листа, чтобы термины совпадали. Те, что выше, — черновик.
- Дисциплины, Дополнения (Background), Достоинства и недостатки.
- Добродетели: Совесть/Убеждённость, Самоконтроль/Инстинкты, Смелость.
- Человечность или Путь (0–10), Сила воли (постоянная и текущая), Запас крови (максимум и трата за ход по поколению), уровни здоровья (Задет, Помят, Ранен, Тяжело ранен, Искалечен, Обездвижен, Без сознания) с типом урона: ударный, летальный, губительный (aggravated), опыт, слабость клана, заметки.

**Поведение.**
- Точки кликабельные. Клик по атрибуту, а затем по способности собирает пул и открывает бросатель из задачи 1 с уже заполненными пулом и подписью; специализация подставляется галочкой.
- Трата Силы воли и крови прямо из листа.
- Игрок видит и правит свой лист. Мастер видит все листы и может править. Другие игроки чужие листы не видят или видят только имя и здоровье (уточнить у автора).
- Хранение: один лист V20 в сжатом JSON весит около 1–2 КБ. Варианты: метаданные комнаты (общий лимит 16 КБ, хватит на 4–5 листов впритык), метаданные жетона персонажа на сцене, метаданные игрока. Сначала измерить лимиты на практике, потом выбрать. Обязательно сделать выгрузку и загрузку листа файлом, чтобы ничего не потерять.

**Готово, когда:** игрок может создать лист, заполнить его, бросить из него пул, и лист переживает перезагрузку и повторный вход в комнату.

## 3. Кнопка карты в Owlbear

В расширение добавить пункт, который открывает сайт карты в попапе Owlbear (`OBR.popover`) или в новой вкладке. Карта остаётся отдельным сайтом, расширение только даёт к ней быстрый доступ. Личные пометки в попапе будут храниться отдельно от обычной вкладки браузера, поэтому стоит написать об этом в интерфейсе.
