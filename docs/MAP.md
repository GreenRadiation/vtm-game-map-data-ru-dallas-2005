# Как устроена карта

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | Оболочка страницы. Подключает шрифты, стили и скрипт. |
| `assets/style.css` | Все стили. Цвета заданы токенами в `:root`, есть тёмная тема. |
| `assets/app.js` | Вся логика: загрузка данных, отрисовка досок, карточка клетки, личные пометки, ссылки на клетки. |
| `data/map.json` | Общие данные всех клеток. Единственный источник правды для описаний и меток. |
| `.nojekyll` | Говорит GitHub Pages отдавать файлы как есть. |

Сборки нет: это чистые HTML, CSS и JS, и GitHub Pages отдаёт их напрямую из ветки `main`.

## Сетки и координаты

Три доски заданы в `BOARDS` в начале `assets/app.js`. У каждой есть число столбцов и рядов и границы в градусах (`n`, `s`, `w`, `e`). Столбцы обозначены буквами слева направо, то есть с запада на восток. Ряды обозначены цифрами сверху вниз, с севера на юг.

| Доска | Ключ | Сетка | Север | Юг | Запад | Восток | Клетка |
|---|---|---|---|---|---|---|---|
| Даллас | `city` | 9×9 | 33.02 | 32.62 | −96.99 | −96.55 | ≈4,6 × 4,9 км |
| Центр Далласа | `core` | 8×8 | 32.842222 | 32.753333 | −96.843333 | −96.745556 | ≈1,14 × 1,23 км |
| Форт-Уэрт | `fw` | 9×9 | 33.00 | 32.60 | −97.55 | −97.11 | ≈4,6 × 4,9 км |

Клетка для точки с широтой `lat` и долготой `lon`:

```
столбец = floor((lon - w) / ((e - w) / cols))   → буква A, B, C…
ряд     = floor((n - lat) / ((n - s) / rows)) + 1
```

Карта центра выровнена ровно по большим клеткам D5, E5, D6, E6: её границы совпадают с границами этих клеток, и каждая большая клетка делится на 4×4 маленьких. A–D 1–4 = D5, E–H 1–4 = E5, A–D 5–8 = D6, E–H 5–8 = E6. На доске центра эти четверти разделены толстыми линиями, а на большой карте четыре клетки обведены пунктиром (`ZOOM` в `app.js`).

Расстояние в карточке считается от центра клетки до отеля Anatole (`ORIGIN`, 32.8005, −96.8277) по прямой, грубой плоской формулой: 1° долготы ≈ 93,3 км, 1° широты ≈ 111 км.

Если кто-то захочет добавить ещё одну детальную доску (например, центр Форт-Уэрта), её стоит так же выровнять ровно по клеткам большой карты.

## Формат data/map.json

```json
{
  "schema": 1,
  "updated": "2026-10-04",
  "cells": {
    "core:B4": {
      "name": "Отель Anatole и Market Center",
      "terrain": "",
      "marker": "haven",
      "label": "Отель Барона",
      "summary": "Огромный отель Барона и оптовые выставочные центры.",
      "details": "Первый абзац.\n\nВторой абзац.",
      "notes": ""
    }
  }
}
```

Ключ клетки — `доска:координата`, например `city:D5`, `core:B4`, `fw:E6`. Должны быть все клетки: 81 для `city`, 64 для `core`, 81 для `fw`.

| Поле | Значение |
|---|---|
| `name` | Короткое название, оно же подпись внутри клетки. 1–4 слова. |
| `terrain` | Местность: `""` — город, `"no"` — другой город (не Даллас или не Форт-Уэрт), `"water"` — вода, `"green"` — лес, пойма, пустоши. |
| `marker` | Метка хроники: `""`, `"haven"` — убежище котерии (светло-зелёная рамка), `"ally"` — союзники (бирюзовая), `"hostile"` — враждебность (красная), `"important"` — важное место (янтарная). |
| `label` | Подпись метки, например «Элизиум». Показывается чипом в карточке. |
| `summary` | Одна строка под заголовком. |
| `details` | Подробное описание. Абзацы разделяются пустой строкой (`\n\n`). |
| `notes` | Заметки мастера, видны всем отдельным блоком «Заметки мастера». Обычно пусто. |

Метка и местность независимы: клетка может быть другим городом и одновременно враждебной.

## Личные пометки

Хранятся в `localStorage` под ключом `vtm-dallas-2005.personal.v1` в виде:

```json
{"cells": {"core:B4": {"marker": "hostile", "label": "Засада", "notes": "…"}}, "updated": "…"}
```

Личная метка на доске перекрывает общую. Общие данные при этом не меняются. Экспорт и импорт работают с тем же форматом. При импорте пометки для совпадающих клеток заменяются пометками из файла.

## Ссылки на клетки

Адрес вида `#city-D5`, `#core-B4` или `#fw-E6` открывает нужную доску и клетку. При клике адрес обновляется сам.

## Правила для описаний клеток

Эти правила вытекают из требований автора, их стоит соблюдать при любых правках.

1. Всё по состоянию на 2005 год. Если факт не удаётся проверить для 2005 года, лучше не писать его вовсе, чем гадать. Ничего, что появилось после 2005 года (Klyde Warren Park, Trinity Groves, AT&T Stadium, Perot Museum и так далее), упоминать нельзя.
2. Объект описывается в той клетке, куда он реально попадает по координатам. Перед добавлением объекта считай клетку по формуле выше.
3. Клетки внутри города описываются подробно: из чего физически состоит клетка (кварталы, улицы, шоссе, здания), кто там живёт, что там ночью, насколько безопасно, есть ли полиция, чем место полезно вампиру (где охотиться, где спрятаться, где найти покровителей). Обычно это 60–160 слов в одном-двух абзацах.
4. Клетки соседних городов и сельские окраины описываются одним-двумя предложениями.
5. Язык простой и живой, как у знающего друга, который объясняет мастеру из постсоветского пространства, ни разу не бывавшему в Техасе. Короткие ясные предложения, без канцелярита, без маркированных списков и эмодзи, без рекламного тона. Википедию не копировать.
6. Названия мест транслитерируются по-русски («Кэмп-Боуи-бульвар», «Дип-Эллум»), а названия учреждений можно оставлять по-английски («Kimbell Art Museum», «Parkland»), если так естественнее.
7. На карте нет личных секретов игроков (например, убежищ их персонажей) и закулисья мастера, только то, что знает вся котерия. Закулисье записывается в `docs/NOTES.md`.
8. Реальные люди упоминаются только как исторический фон. Сюжетные роли (союзник, гуль, враг) реальным людям не приписываются: если в хронике есть аналог реального человека, на карте он описывается без имени или придумывается вымышленный.

## Внешний вид

Цвета и шрифты заданы токенами в начале `assets/style.css`. Шрифты: Unbounded (заголовки), Golos Text (текст), JetBrains Mono (координаты и подписи), все с Google Fonts. Тёмная тема включается автоматически по системной настройке. Страница должна работать на ширине телефона (около 390 px) без горизонтальной прокрутки.
